    System Architecture

    How the DataInsideData.com Platform Works

    The platform connects content authoring, static-site generation, CI/CD, deployment, DNS, analytics, and public presentation as a coordinated publishing system.

    🧱 Platform Scope

    More Than a Static Website

    The project combines several technical disciplines within one production platform:

    • Jekyll static-site generation
    • Minimal Mistakes theme architecture
    • Custom layouts, includes, and SCSS
    • Git-based content management
    • Automated deployment workflows
    • Cloud DNS configuration
    • Analytics instrumentation
    • Documentation-driven publishing

    The result is a continuously evolving technical publishing platform rather than a collection of independently maintained HTML pages.

    🗂️ Source Architecture

    Private Source of Truth

    The production workflow separates development from public deployment.

    • Private repository → source code and authoring
    • Jekyll → static-site generation
    • GitHub Actions → build and deployment automation
    • Public repository → generated production output

    This separation keeps development logic, configuration, and publishing workflows isolated from the repository that serves the compiled public site.

    ⚙️ CI/CD

    Automated Publishing Pipeline

    Changes move through a Git-based workflow before reaching production.

    • Feature development and content updates
    • Source control and branch management
    • Jekyll build execution
    • Generated-site validation
    • GitHub Actions deployment
    • Public GitHub Pages publication

    The deployment workflow reduces manual publishing work while keeping production output reproducible.

    ☁️ Delivery + Observability

    Public Platform Layer

    The generated platform is delivered through a combination of GitHub and AWS services.

    • GitHub Pages → static hosting
    • AWS Route 53 → domain and DNS management
    • HTTPS → encrypted public delivery
    • GA4 → usage and traffic analytics
    • Jekyll SEO → metadata and discoverability
    • Sitemap and feed generation → content discovery

    Together these services form the public delivery and observability layer of DataInsideData.com.

    Publishing Model

    From Source to Production

    The platform uses a deliberately separated development and publishing architecture.

    ⚙️ Production Publishing Model

    The private repository contains the maintainable source system: Jekyll content, configuration, layouts, includes, styling, scripts, and deployment logic.

    GitHub Actions builds that source into static production output and publishes the generated site to the public GitHub Pages repository.

    AWS Route 53 then connects the custom DataInsideData.com domain to the production deployment.

    This creates a clear boundary between the development layer and the public presentation layer.
